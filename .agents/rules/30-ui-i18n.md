# UI and i18n Rules

These rules apply to Ant Design Vue, layout, forms, tables, shared UI components, and vue-i18n.

## UI Direction

Use a traditional admin UI style.

The UI should be:

- clean
- flat
- readable
- practical
- consistent

Avoid:

- trendy effects
- glassmorphism
- heavy shadows
- large rounded corners
- gradients
- excessive animations

## Border Radius

Avoid border radius by default.

If necessary, use max `4px`.

Avoid:

```vue
<a-card class="rounded-2xl shadow-xl" />
```

Prefer:

```vue
<a-card class="rounded border" />
```

Only use `rounded` if it maps to a small radius.

## Shadows

Avoid shadows unless needed for hierarchy.

Allowed:

- dropdowns
- modals
- popovers
- floating menus

## Ant Design Vue

Use Ant Design Vue consistently.

Prefer Ant Design Vue for:

- forms
- inputs
- selects
- tables
- pagination
- modals
- buttons
- tags

Do not rebuild Ant Design components manually unless necessary.

## Inline Styles

Do not use inline `style` attributes in templates.

Do not use inline style objects in scripts.

Use class names or utility classes instead.

## Forms

Use `a-form` and `a-form-item`.

```vue
<a-form :model="formState" layout="vertical" :rules="rules" @finish="handleSubmit">
  <a-form-item name="email">
    <a-input v-model:value="formState.email" />
  </a-form-item>
</a-form>
```

## Tables

Use `a-table` for admin lists.

Keep columns defined in script.

```ts
const columns = computed(() => [
  {
    title: t('user.name'),
    dataIndex: 'name',
    key: 'name',
  },
]);
```

## i18n

Use vue-i18n for user-facing text.

Do not hardcode labels that appear in the UI.

Use translation keys for:

- form labels
- buttons
- page titles
- table columns
- empty states
- validation messages
- success/error messages

Good:

```ts
t('auth.emailLabel');
t('user.tableName');
t('appointment.status');
```

Keep translation keys readable and grouped by module.
